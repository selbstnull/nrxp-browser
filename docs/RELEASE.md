# Выпуск релиза

Релизы собирает GitHub Actions workflow **release** (`.github/workflows/release.yml`), **только вручную**:
Actions → **release** → **Run workflow**. Файл написан в Linux-окружении и ещё ни разу не запускался на раннерах; сборка с движком
под Windows и macOS нигде не проверялась — поэтому по умолчанию релиз создаётся **черновиком** и **пре-релизом**.

## Что делает

| Джоба | Результат | Примечание |
|---|---|---|
| `prepare` | проверка версии (semver) и что тег `v<версия>` свободен | |
| `linux` | `nrb-<v>-linux-x86_64.tar.gz`, `nrb_<v>_amd64.deb` | с видео (`--features media`, GStreamer), зависимости deb — по `ldd` |
| `node` | `nrb-node-<v>-linux-x86_64-musl` | статический узел без движка (для VPS) |
| `windows` | `nrb-<v>-windows-x86_64.zip` | без видео; **не проверялось** |
| `macos` | `nrb-<v>-macos-arm64.dmg` | `.app` с ad-hoc подписью, без нотаризации; **не проверялось** |
| `android` | `nrb-<v>-android-arm64.apk` | по умолчанию выключено; отладочная подпись, не для магазина; очень долго |
| `release` | `SHA256SUMS`, `manifest.json` (+ `.sig`), GitHub Release | запускается, если ни одна выбранная джоба не упала |

Входы: `version` (без «v»), `notes`, `draft`, `prerelease`, чекбоксы платформ, `servo_repo`/`servo_ref` (по умолчанию
`selbstnull/nrxp-servo` ветка `nrxp/0.7`).

## Подпись манифеста обновлений

Манифест (`nrb release manifest`) подписывается ed25519-ключом, которым проверяет обновления `nrb update`. Ключ создаёт владелец
**один раз** и хранит секретно:

```bash
nrb release keygen          # создаст update.key (СЕКРЕТ, 0600) и update.pub
base64 -w0 update.key       # значение для секрета репозитория RELEASE_SIGNING_KEY
```

Публичный ключ `update.pub` зашивается в сборки (как — `docs/PROGRESS.md`, раздел обновлений). Без секрета `RELEASE_SIGNING_KEY`
workflow создаёт манифест **без подписи** и пишет предупреждение в описании релиза: автообновление такому манифесту не поверит.
Секрет не должен попадать в логи; workflow пишет ключ во временный файл с правами 0600 и удаляет его сразу после подписи.

## Как выпустить

1. Убедитесь, что `main` собирается (workflow **platforms** зелёный: `portable`, затем `engine` на нужных ОС).
2. Actions → **release** → Run workflow: версия `0.1.0`, оставьте «draft» и «prerelease», отметьте нужные платформы.
3. Скачайте артефакты из черновика Release и проверьте (`sha256sum -c SHA256SUMS`, запуск на чистой машине).
4. Опубликуйте черновик в интерфейсе GitHub (тег `v<версия>` создаётся на коммите, с которого запущен workflow).

Если джоба платформы упала — снимите её чекбокс и запустите заново (тег появляется только при успешном `release`, повторный
запуск с той же версией возможен). Gitea этот workflow не читает (`.gitea/workflows/` — старые `ci.yml` и `servo.yml`).
