# nrxp-servo — форк Servo под этот браузер

План доработки недостающего функционала движка лежит в самом форке: **`~/netrunner/nrxp-servo/docs/nrxp/PLAN.md`**
(ветка `nrxp/0.7`, база — тег `v0.7.0`, remote `upstream` = `servo/servo`). Репозиторий на GitHub/Gitea для форка **не создавался**.

Кратко (этапы N0–N14): бутстрап и сборка по путям → срочные исправления (WebGL при остановке, хранилище без профиля, prefs,
PerformanceObserver) → **сеть через коннектор встраивателя** (NRXP без loopback-прокси; фундамент для остальных) → загрузки →
данные сайтов → поиск по странице → печать/PDF → медиа и MSE → Service Workers → WebRTC через туннель → HTTP/3 → пароли/формы/a11y →
мультипроцесс и песочница → расширения → сопровождение форка и апстрим.

Что можно сделать в браузере **без** форка уже сейчас: загрузки по эвристике с куками (`SiteDataManager::cookies_for_url`, N3a) и
поиск по странице через `evaluate_javascript` (N5a).

Связь с итерациями браузера: I6.1 (загрузки) ← N3; I10 (HTTP/3) ← N10; I11 (герметичность, остаток) ← N2, N12; I13 ← N7, N8;
I12 (расширения) ← N13.

## Как браузер использует форк (N0, сделано 2026-10-09)

`scripts/setup-upstream.sh` генерирует `.cargo/config.toml` (в git не хранится) с `[patch.crates-io]` для **всех** крейтов `servo*` форка
(`scripts/gen-servo-patch.py`); каталог форка — `NRXP_SERVO_DIR` (по умолчанию `../nrxp-servo`). Подменять нужно все крейты сразу: частичная
подмена даёт две несовместимые копии типов. С N2 форк **обязателен** (`ServoBuilder::network_connector`); без него скрипт завершается с понятной ошибкой. Легаси-патч `patches/servo/0001-*` оставлен только как история.
Проверено: сборка `-p nrb --features servo` на форке (3 мин debug), `gui-smoke` зелёный, корпус 43/52 (шум ±4% относительно 44/52), WebSocket в
герметичном режиме работает. `Cargo.lock` теперь в «форковом» состоянии (у подменённых пакетов нет `source`/`checksum`); версии сторонних крейтов не менялись.

## N2 — сеть через коннектор (сделано 2026-10-09)

Все исходящие TCP-соединения Servo (HTTP(S), WebSocket) идут через `NetworkConnector` браузера → `NrxpTransport` → узел; локальный
HTTP-CONNECT прокси и патч WebSocket для движка не нужны (прокси остался только для `nrb corpus`). Имя хоста уходит выходной ноде
нерезолвленным. Герметичный режим упростился: пустой netns + коннектор, без релея и unix-сокета. Подробности и проверки — в `docs/PROGRESS.md`
и в плане форка (`nrxp-servo/docs/nrxp/PLAN.md`, N2).
